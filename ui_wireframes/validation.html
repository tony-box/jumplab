Tolerance policy

Tolerances must come from measured error at the shipped timestep, with headroom — not from round numbers chosen because they look tidy. A tolerance that every timestep passes proves nothing; the suite has to be able to fail.

// 1. Measure at the shipped Δt.   2. Set tolerance ≈ 3–5× that error.
// 3. Verify a coarser Δt actually fails.  A suite that always passes is decoration.

interface Check {
  id: string;
  label: string;
  describe: string;              // the closed form it is compared against
  run(dt: number): { measured: number; unit: string };
  tolerance(dt: number): number;   // may scale with dt — say so in the row
}

type CheckResult = Check & {
  measured: number;
  margin: number;                 // tolerance / measured, ≥1 passes
  status: 'pass' | 'fail';
};

// Observed order between consecutive sweep rows:
//   order = log2(errCoarse / errFine)   → ≈1.0 for semi-implicit Euler
  • Report margin, not just pass/fail. A check passing at 1.05× is a warning even though it is green.
  • Exact means exact. Where an integrator is analytically exact (trapezoidal velocity under constant gravity), say exact in the tolerance column rather than inventing an epsilon.
  • Never round a failure into a pass. Display precision is a formatting concern; comparison happens on the raw value.
  • Wall time is a published number. If the suite grows past the budget, it stops being run and stops being true.

const runSuite = async () => {
  const t0 = performance.now();
  const checks = CHECKS.map(c => evaluate(c, dt));
  const sweep  = convergenceSweep([1/60, 1/120, 1/240, 1/480, 1/960]);
  const hashes = [0,1,2].map(() => hashFrames(solveReference(dt)));
  setRes({ checks, sweep, hashes, wallMs: performance.now() - t0 });
};

Acceptance checks

  • Selecting 1/60 s produces at least one genuine failure — if everything still passes, the tolerances are decorative.
  • Observed order sits within ±0.05 of 1.0 across the sweep for the shipped integrator.
  • Three determinism repeats produce identical hashes, and the hash box renders one hash per line with its newlines honoured.
  • Reported wall time reflects actual measurement and stays under the published budget.
  • No row in the analytical table shows a status without a measured value beside it.
  • Every pending row names an owner and a gate; none is left as a bare "todo".
