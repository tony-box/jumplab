Modelling note — the arm is derived, not authored

The first build of this screen used forward kinematics for the whole figure: shoulder and elbow angles were authored like any other joint, and the hand landed wherever the chain ended. That silently violated the model — hands are physically constrained to the handlebars. Move the hip and the hands drifted off the bar.

// Correct: the bar is a fixed world point; the arm is a 2-link IK chain.
// Driven joints: ankle, knee, hip, spine.  Derived: shoulder, elbow.

function solveArm(shoulderPos: Vec2, grip: Vec2, upper: number, fore: number) {
  const d = clamp(dist(shoulderPos, grip), Math.abs(upper - fore) + EPS, upper + fore - EPS);
  const elbowInterior = Math.acos((upper*upper + fore*fore - d*d) / (2*upper*fore));
  const elbow = Math.PI - elbowInterior;          // flexion from straight
  const base  = angleTo(shoulderPos, grip);
  const off   = Math.acos((upper*upper + d*d - fore*fore) / (2*upper*d));
  const shoulder = base + off;                     // elbow-DOWN branch
  return { shoulder, elbow };
}
  • Clamp before acos. Reach beyond upper + fore is a valid user drag; it must clamp, flag out of reach, and keep the hands on the bar — not produce NaN.
  • Pick the elbow-down branch. Both IK solutions are geometrically valid; only one is anatomically right on a bike. The first build solved elbow-up and the figure read as broken.
  • Use one angle convention. Derived shoulder and elbow angles must be expressed in the same convention as the ROM table, or you get a 156° reading against a 110° limit and the saturation count becomes meaningless.
  • Achieved follows achieved. The achieved arm is solved from the achieved body, not PD-chased independently — otherwise the ghost's hands leave the bar.

Acceptance checks

  • Hands remain coincident with the grip point for every reachable pose and every keyframe in the clip — verify by asserting dist(hand, grip) < 1e-6 across a sweep of hip positions.
  • Derived shoulder and elbow angles always fall inside the ROM table's published range, in the same convention the table uses.
  • Dragging a slider from end to end never loses keyboard focus and fires no full list re-render.
  • Adding a keyframe at the playhead leaves the interpolated curve unchanged.
  • Changing entry speed in the workbench re-times the clip without altering any keyframe's s.
  • Saturation count matches the number of distinct joints flagged in the table — the pill and the table can never disagree.
  • Bike/Pose radio arrow keys, numeric native stepping, and keyframe list navigation operate independently with visible focus.
  • At the iPad Pro 11 viewport, the active rail stacks below the shared fixed-size preview with no horizontal page scroll; long conflicts wrap.
