Sheet 00 — system

Wireframes & build contract

These six sheets describe the 2D MTB Jump Lab UI at a level a coding agent can implement from: every region carries a stable data-od-id, a named React component, a behaviour contract, and a data binding. The high-fidelity prototype next door is the visual target; these sheets are the structural target. Where the two disagree, the prototype wins on pixels and the sheet wins on behaviour.

How to read a sheet

7Numbered pin. Anchors a region to its row in that sheet's region table. Numbers are sheet-local.
Solid box. A region that is always rendered.
Dashed box. Conditional — hidden tab panel, empty state, or a region that only appears once a baseline is pinned.
Light hatch. A drawn surface: SVG chart or plot, not DOM layout.
Dark hatch. The instrument stage — a <canvas> the worker's frame stream is replayed into.
idMono label. The literal data-od-id to put in the markup. Playwright selectors and comment-mode targeting both depend on these.

Shared data contract

// packages/schema — versioned, shared verbatim by web/ and physics/.
// Every field is SI. Angles are radians on the wire, degrees only at the UI edge.

export interface Scenario {
  schemaVersion: number;          // bump = migration required both sides
  id: string; name: string;
  jump: JumpSpec; rider: RiderSpec; bike: BikeSpec;
  entry: { speed: number; startX: number };
  poseClip: PoseClip;
  solver: { dt: number; substeps: number; ccd: boolean; seed: number };
}

export interface JumpSpec {
  kind: 'table' | 'gap' | 'stepup' | 'stepdown';
  lipHeight: number; lipAngle: number; transitionRadius: number;
  gap: number; stepDelta: number;
  landingAngle: number; landingLength: number; rollout: number;
}

export interface RiderSpec {
  height: number; mass: number; legRatio: number; armRatio: number;
  strengthScale: number; kp: number; kd: number;
  joints: Record<JointId, { min: number; max: number; tauMax: number }>;
}
export type JointId = 'ankle' | 'knee' | 'hip' | 'spine' | 'shoulder' | 'elbow';

export interface BikeSpec {
  wheelSize: 26 | 27.5 | 29; wheelbase: number; chainstay: number;
  bbHeight: number; mass: number;
  fork: { travel: number; sag: number; springRate: number; damping: number };
}

/* Keyframes are anchored to s — along-track distance from the lip, in metres.
   Never to time. Changing entry speed re-times the clip without re-authoring it. */
export interface PoseClip {
  id: string; name: string;
  interpolation: 'cubic' | 'linear' | 'step';
  keys: { s: number; label: string; targets: Record<JointId, number> }[];
}

/* ---- worker boundary ---------------------------------------------- */
export type SolveRequest  = { type: 'solve'; runId: string; scenario: Scenario };
export type SolveProgress = { type: 'progress'; runId: string; pct: number };
export type SolveResult   = { type: 'result'; run: RunResult };
export type SolveError    = { type: 'error'; runId: string; code: string; message: string };

export interface RunResult {
  runId: string; scenarioHash: string;   // hash ⇒ determinism check + cache key
  frames: Frame[];                     // immutable; Canvas replays, never recomputes
  phases: { name: 'approach' | 'transition' | 'air' | 'landing' | 'rollout';
            tStart: number; tEnd: number }[];
  metrics: Metrics;
  telemetry: { solverError: number | null; saturatedJoints: JointId[];
               warnings: string[] };
}

export interface Frame {
  t: number; bike: { x: number; y: number; pitch: number };
  wheels: [Contact, Contact];        // [rear, front]
  joints: Record<JointId, { angle: number; target: number; torque: number }>;
  com: { x: number; y: number; vx: number; vy: number };
  forkTravel: number; energy: { ke: number; pe: number; motorWork: number };
}
interface Contact { x: number; y: number; normalForce: number | null; contact: boolean }

/* A metric is never a bare number. It carries where it came from, so the UI
   can render 'measured', 'estimate', or a blank row — and never a plausible lie. */
export interface Metric {
  value: number | null;
  unit: string;
  source: 'measured' | 'estimate' | 'pending-core';
}
export type Metrics = Record<MetricId, Metric>;
The source field is the most important thing in this contract. It is what lets the UI keep Peak wheel load, Motor work, Contact impulse and Solver error visibly blank until the Rapier core is attached, instead of filling them with something that looks plausible. Render 'pending-core' as a dimmed — — — plus a one-line reason; never as 0.

Build order

  1. Schema package + worker boundary

    Ship Scenario, RunResult, Frame, Metric and the four message types first, with a stub worker that returns a kinematic approximation. Every screen below can then be built and tested before Rapier exists.

  2. App shell + Workbench read-only

    Topbar, three-column grid, stage with DPR-correct canvas, replay of a canned RunResult. No editing yet. Locks the hardest layout problem early.

  3. Workbench inputs → solve → metrics

    Wire the rails to the store, the primary action to the worker, and the metrics rail to Metrics. Add pin-baseline and the Δ column last.

  4. Designer

    Reuses <Stage> and the rail shell for static bike geometry and pose keys. The IK bar constraint remains part of Pose mode.

  5. Run report

    Pure read view over two RunResults. No new state, no new inputs.

  6. Library + Validation

    Both are document-flow screens over static data plus derived numbers. Validation's harness is the one place that may run physics on the main thread.

Non-negotiables

Honesty

Measured, estimated, or blank — nothing else. A metric with source:'estimate' renders with a visible est. marker and a sentence saying what it is an estimate of. A 'pending-core' metric stays blank. The tool teaches physics; a fabricated number is the one bug that makes it worthless.

Determinism

Same scenarioHash ⇒ byte-identical frames. The UI must never introduce non-determinism: no Date.now() in the sim path, no animation-frame-derived stepping, no floating-point accumulation in the scrubber. Playback reads an array by index.

Replay, don't recompute

Physics runs at a fixed timestep in the worker. Canvas draws at 60fps by interpolating between stored frames. Scrubbing, slow motion and frame-stepping all index the same immutable array — none of them re-enter the solver.

Accessibility floor

Body text ≥ 4.5:1, large text and icons ≥ 3:1, and contrast never drops on hover. Every focusable element gets a visible :focus-visible ring. Canvas is decorative to AT — the metrics rail and tables are the accessible representation of the run, so they must stay in the DOM.
